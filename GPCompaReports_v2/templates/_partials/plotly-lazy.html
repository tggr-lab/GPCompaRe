{# Plotly, loaded when a chart is about to be seen instead of blocking first paint. Until the library arrives, window.Plotly is a small stand-in. The pages only ever call newPlot (and chain .then on it), relayout, restyle and Plots.resize; the stand-in queues those calls, returns promises, and replays them against the real library: per chart, in order, each call awaiting the one before it. A second newPlot for a chart whose first is still pending (site.js and a report's own DOMContentLoaded handler both start the charts before the library is there) returns the first call's promise instead of drawing the chart again. The real script is injected when the first chart container comes within 800 px of the viewport, or a couple of seconds after the page has loaded when the connection is not metered. The real library replaces window.Plotly when it loads, so every later call goes straight to it. If it cannot be loaded, the stand-in removes itself and the page behaves as it did when the script tag failed (no charts, no errors). Nothing here touches the markup or the chart data of a report section. #}
